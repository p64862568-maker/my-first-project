# Отчет по практике и документация проекта: API сервис заметок

### Часть 1. Подготовка и основы (Скрипт-обработчик логов)
В общем, в первой части я сделал скрипт на питоне, который берет файл server.log, читает его построчно и ищет там критические ошибки типа ERROR, CRITICAL и FATAL. Если находит, то вытаскивает из начала строки IP-адрес и считает, сколько раз этот IP накосячил, а в конце скидывает всю эту статистику в файл report.txt. По поводу оптимизации и вложенных циклов: если делать в лоб, то для каждой строчки лога питон будет гонять цикл по всем трем ошибкам до самого конца, а это долго, если лог огромный. Я оптимизировал это дело так, что поставил проверку через флаг и прерывание break. То есть, как только скрипт нашел в строке слово ERROR, он сразу обрывает внутренний цикл и идет к следующей строке, не тратя время на проверку остальных слов. Для запуска нужно просто положить скрипт log_parser.py и текстовый файл server.log с логами в одну папку на компе, запустить скрипт через консоль командой python log_parser.py и потом открыть появившийся файл report.txt, где будет лежать готовый результат. Код написан просто, без импорта сложных библиотек, чтобы не запутаться и чтобы работало без лишних настроек.

### Часть 2. Базы данных и расширение API сервиса
В этой части задания я перевел проект на полноценную базу данных PostgreSQL и подключил библиотеку SQLAlchemy, чтобы работать через ORM-модели, а не писать SQL-запросы руками. Для контроля таблиц я поставил себе DBeaver, подрубился к локальному Постгресу и смотрел, как там создаются структуры. В коде я сделал две таблицы: одну для самих заметок, а вторую для категорий, чтобы можно было группировать записи. Связал их через ForeignKey, то есть получилась связь один-ко-многим, когда у одной категории может быть куча заметок. Чтобы препод не придрался к объему данных, я добавил в GET-запрос фильтрацию и пагинацию. Теперь, если дописать в адресную строку параметры, можно отфильтровать заметки по конкретной категории, а пагинация разбивает весь список на страницы по несколько штук, под капотом тут работают стандартные SQL-команды LIMIT и OFFSET. Также полностью реализовал весь круг CRUD: методы POST для добавления записей (INSERT), PUT для изменения (UPDATE) и DELETE для удаления.

### Часть 3. Тестирование и деплой проекта
В финальной части работы я занялся тестированием приложения и его запуском на удаленном сервере. Для проверки работоспособности кода я написал юнит-тесты с использованием фреймворка pytest. Чтобы тесты не забивали основную базу данных, в настройках фикстуры я временно подменяю адрес базы на тестовую sqlite, которая создается прямо в оперативной памяти компьютера и очищается после прогона тестов. Написанные тесты проверяют базовые вещи, такие как получение пустого списка заметок при первом запуске и успешный статус создания новой заметки через POST-запрос. Далее для автоматизации деплоя я завернул все приложение в Docker. Для этого был написан Dockerfile на базе легковесного образа питона, куда копируются файлы проекта и ставятся все нужные библиотеки из requirements.txt. В качестве серверного процесса для запуска в Docker я прописал gunicorn, который работает гораздо стабильнее стандартного встроенного отладочного сервера Flask. Что касается реального деплоя, на VPS сервере все настраивается через связку gunicorn и nginx, где nginx выступает в роли обратного прокси, принимает внешние запросы из интернета на 80 порту и перенаправляет их внутрь на gunicorn. Для быстрого деплоя без своего сервера проект также можно закинуть на хостинги типа Render или Railway, где достаточно просто привязать свой гитхаб репозиторий с Dockerfile, и сервис соберется и запустится автоматически в облаке.

### Инструкция по локальному запуску проекта
1. Установить все необходимые библиотеки на компьютер командой в терминале:
pip install flask flask_sqlalchemy psycopg2-binary pytest gunicorn
2. Создать пустую базу данных в PostgreSQL (например, через DBeaver) и прописать настройки подключения к ней в файле app.py в строчке app.config['SQLALCHEMY_DATABASE_URI'].
3. Запустить проект командой:
python app.py
4. Для запуска тестов прописать в консоли команду:
pytest test_app.py

### Инструкция по запуску через Docker
1. Собрать контейнер с приложением:
docker build -t my-api-service .
2. Запустить контейнер на 5000 порту:
docker run -p 5000:5000 my-api-service

### Примеры API-запросов (для проверки в Postman или Terminal через curl)

1. Запрос на создание новой заметки (POST):
curl -X POST http://localhost:5000/notes -H "Content-Type: application/json" -d "{\"title\": \"Купить хлеб\", \"content\": \"Взять белый и бородинский\", \"category_id\": 1}"

2. Запрос на получение всех заметок с пагинацией (GET):
curl -X GET "http://localhost:5000/notes?page=1&per_page=5"

3. Запрос на обновление заметки (PUT):
curl -X PUT http://localhost:5000/notes/1 -H "Content-Type: application/json" -d "{\"title\": \"Новый заголовок\", \"content\": \"Новый текст\"}"

4. Запрос на удаление заметки (DELETE):
curl -X DELETE http://localhost:5000/notes/1
